# MiniMax H3 真人短视频全能参考创作指南

本文用于指导使用 MiniMax H3 全能参考模式（Ref2VA）创作 3–5 分钟真人叙事短视频。适用于两类起点：

- 已有完整剧本，需要将其拆解并生成成片。
- 只有一个想法，需要先发展为可拍摄剧本，再进入视频生产。

这不是“一条提示词生成一部短片”的玩法。MiniMax H3 单次只能生成 4–15 秒视频，因此 3–5 分钟成片必须被拆成若干独立生成单元，再通过剪辑、调色、配音、混音和字幕包装完成。长片成败的决定因素不是某条 Prompt 写得多华丽，而是**剧本是否可执行、资产是否统一、镜头是否可衔接、生成是否有版本记录、后期是否能遮住模型边界**。

---

## 1. 先建立正确预期

### 1.1 H3 生成的是镜头素材，不是完整长片

H3 的单次输出时长为 4–15 秒。3–5 分钟即 180–300 秒：

- 理论上全部使用 15 秒片段，需要至少 12–20 条素材。
- 实际真人剧情通常以 6–12 秒作为一个生成单元，更容易控制人物、动作和对白。
- 普通叙事项目通常会形成约 20–50 个可用生成单元；快切、动作或多角色项目可能更多。
- 关键镜头通常需要 2–4 个候选版本，实际生成次数会显著高于最终镜头数。

不要为了减少生成次数，把每条都硬撑到 15 秒。一条素材同时塞入三次转身、两段对白、一次换装和一次爆炸，省下的是文件数量，收获的是连续性事故现场。

### 1.2 每次生成都是相对独立的

H3 不会自动记住上一条素材中的人物状态。跨镜头一致性必须依靠：

- 稳定的角色参考图与音色参考。
- 明确的服装、发型、妆容、道具和场景定义。
- 上一条批准素材的末帧或关键帧。
- 每条 Prompt 中重新声明的必要特征。
- 项目级连续性记录。

不要连续十几次只拿上一次生成结果继续喂模型。递归参考会把小偏差逐步放大，应定期重新加入主角色、主服装和主场景的原始参考进行校准。

### 1.3 首个项目先做 30–60 秒样片

正式生产 3–5 分钟前，先完成一段能代表全片难度的样片，至少包含：

1. 主角正面近景和自然表演。
2. 一段完整对白及口型。
3. 两个角色同框或正反打。
4. 一个明确动作与道具交互。
5. 至少一次跨镜连续性衔接。
6. 最终配乐、环境声和字幕的后期效果。

样片验收通过后再锁定人物、音色、画面风格和生产方法。样片失败时，修改资产和流程；不要把同样的问题复制到整部片的四十个镜头里。

## 2. H3 硬限制与项目策略

| 项目 | H3 限制 | 长片生产策略 |
| --- | --- | --- |
| 单次输出时长 | 4–15 秒，按项目约定使用整数 | 将剧本拆成独立生成单元；每条只承担一个主要叙事动作 |
| 提示词长度 | 不超过 7000 字符 | 一条 Prompt 只描述当前生成素材，不放整部剧本 |
| 参考图片 | 最多 9 张；单张不超过 30 MB | 每条只选真正生效的 1–5 张，不要把资产库全塞进去 |
| 参考视频 | 最多 3 段；每段 2–15 秒；总时长不超过 15 秒；单段不超过 50 MB | 分别承担动作、运镜、表演或源视频职责 |
| 参考音频 | 最多 3 段；每段 2–15 秒；总时长不超过 15 秒；单段不超过 15 MB | 对白按镜头切分；区分音频复制与音色参考 |
| 混合输入 | 总文件数最多 12 个 | 建立每镜头素材清单，优先保留人物和关键连续性资产 |
| 音频单独输入 | 不允许，必须搭配至少一张图片或一段视频 | 音色参考始终与对应角色图或画面素材同时上传 |
| 画面输出 | 基础生成通常为 768p、24 FPS、原生立体声 | 先低成本完成生成与剪辑锁定，再对最终选中镜头做高分辨率处理 |

全能参考模式可以使用图片作为具体首帧、关键帧或尾帧，但仍须使用 Ref2VA 六字段结构。**不要混入 I2VA/FL2VA/L2VA 的 Base 对齐指令。**

模型、时长、分辨率、画幅等是生成参数，不应塞进结构化 Prompt 正文。建议在每个提示词文件中将它们单独记录。

## 4. 从想法发展为可拍剧本

### 4.1 先填写创作简报

在让 AI 写剧本前，先明确：

```text
项目名称：
一句话想法：
目标时长：3 / 4 / 5 分钟
发布平台与观众：
画幅：16:9 / 9:16 / 其他
类型：爱情 / 悬疑 / 喜剧 / 动作 / 广告剧情 / 其他
真人质感方向：写实电影 / 竖屏短剧 / 纪录片 / 时尚叙事 / 其他
核心人物数量：
主要场景数量：
核心冲突：
希望观众最后产生的感受：
必须出现的情节、对白、物品或画面：
不能出现的内容：
可用参考素材：
对白语言：
制作资源与预算限制：
```

一句话想法至少要包含“谁、想要什么、遇到什么阻碍、失败会怎样”。例如“一个人在雨夜等车”只是画面；“一个准备逃婚的女人在最后一班车到站前，必须决定是否接听未婚夫的电话”才具备短片冲突。

### 4.2 使用分阶段剧本法

不要让 AI 第一次就直接吐出五分钟完整剧本。正确顺序：

1. 生成 3 个不同故事方向。
2. 选择方向并锁定一句话梗概。
3. 生成角色、冲突、转折和结局。
4. 生成节拍表与时长预算。
5. 生成场景列表。
6. 编写含动作、对白和声音的场景剧本。
7. 朗读计时并删改。
8. 锁定剧本后再拆镜头。

用于从想法生成剧本的请求模板：

```text
请根据以下创作简报，为一部使用 MiniMax H3 全能参考模式制作的真人叙事短片设计剧本。

[粘贴创作简报]

生产约束：
1. 最终成片为 3–5 分钟，但每个 AI 生成单元只有 4–15 秒。
2. 控制角色、场景、服装和关键道具数量，优先保证跨镜头一致性。
3. 动作必须可观察、可拆分，不依赖大规模群演或过于复杂的物理互动。
4. 对白必须精炼，给表演、反应和剪辑留出时间。
5. 不要先写完整台词剧本。

第一轮只输出：
- 3 个差异明显的故事方向
- 每个方向的一句话梗概
- 主角目标、阻碍、转折与结局
- 主要制作难点
- 适合 H3 制作的理由与需要规避的问题
```

方向选定后，再要求输出：

```text
请将选定方向发展为可执行剧本方案，按以下顺序输出：
1. 一句话梗概
2. 主题与观众情绪曲线
3. 角色表
4. 百分比节拍表及每段时长预算
5. 场景列表：场次、地点、时间、人物、场景目的、冲突、进入状态、离开状态、预计时长
6. 制作风险和简化建议

先不要拆镜头，不要编写 H3 Prompt。
```

### 4.3 3–5 分钟叙事节奏参考

不同类型可以调整，但至少要有明确变化：

| 成片百分比 | 叙事作用 | 检查问题 |
| --- | --- | --- |
| 0%–10% | 开场钩子 | 前 10–20 秒是否出现人物、异常或悬念？ |
| 10%–30% | 建立目标与规则 | 主角想要什么，观众是否看懂？ |
| 30%–70% | 阻碍升级与关系变化 | 每个场景是否带来新信息或更大代价？ |
| 70%–90% | 决定、对抗或反转 | 主角是否作出不可回避的选择？ |
| 90%–100% | 结果与余韵 | 结局是否回应开场和主题？ |

如果一个场景删掉后剧情没有任何变化，就删掉。三分钟不是给闲聊铺红毯的地方。

### 4.4 剧本格式

每个场景至少包含：

```text
场次：场01
地点/时间：室内，旧公寓客厅，深夜
预计时长：35 秒
出场人物：林夏、周程
场景目的：林夏确认周程隐瞒了车票
进入状态：林夏仍试图相信他
离开状态：林夏决定独自离开

动作：
林夏把湿外套搭在椅背上，看见桌角露出的车票。她没有立即拿起，而是先看向厨房里的周程。

对白：
林夏：<原文对白>
周程：<原文对白>

声音：
窗外雨声；冰箱压缩机间歇启动；手机振动一次。

连续性：
林夏右手有一把湿伞；车票在桌面右侧；周程衬衫袖口卷到手肘。
```

所有对白都应实际朗读并计时。不要只靠字数估算；演员停顿、呼吸、转身和反应都会占用时间。对白无法在镜头时长内自然说完时，优先删词或拆镜，而不是要求角色像开了二倍速。

### 4.5 锁定剧本的门槛

满足以下条件才进入资产制作：

- 故事在目标时长内完整成立。
- 主角目标、冲突、转折和结局明确。
- 场景数量受控，地点转换有必要性。
- 角色数量与参考素材能力匹配。
- 对白已朗读计时。
- 高难动作已被简化或有替代镜头方案。
- 不再修改核心角色、服装和结局。

### 4.6 已有剧本的处理方法

拿到现成剧本后，不要直接逐段翻译成 H3 Prompt。先做一次“可生成性审计”：

- 实际朗读和表演时长是否落在 3–5 分钟。
- 每个场景是否有明确叙事作用和状态变化。
- 主要角色、群演、地点、服装和道具数量是否可控。
- 是否包含多人肢体纠缠、复杂追车、大规模破坏等高风险动作。
- 是否大量依赖难以连续生成的细微物理交互。
- 对白是否过长，是否可通过反应镜头、画外音或插入镜头承载。
- 剧本有没有清楚写出人物进入状态和离开状态。

可使用以下请求模板完成审计与改编：

```text
请将下面的现有剧本改编为适合使用 MiniMax H3 全能参考模式制作的 3–5 分钟真人短视频生产剧本。

[粘贴现有剧本]

约束：
1. 单个 H3 生成单元为 4–15 秒，后续需要拆成多个独立镜头素材。
2. 保留原故事的核心人物、冲突、关键转折、结局和用户提供的原始对白；如需删改对白，先列出建议，不要直接篡改。
3. 控制人物、场景、服装和道具数量，降低跨镜头一致性风险。
4. 将复杂动作拆成可观察的连续状态，必要时建议用反应镜头、插入镜头或画外音替代。
5. 当前阶段不要编写 H3 Prompt。

请按顺序输出：
- 时长与结构诊断
- 不可执行或高风险内容清单
- 简化建议及其对剧情的影响
- 调整后的场景表：场次、地点、人物、目的、冲突、进入状态、离开状态、预计时长
- 需要用户确认的对白删改项
- 资产需求清单
```

改编后的剧本仍须朗读计时并由创作者确认。AI 给出的“预计 30 秒”只是规划值，不是时间魔法；嘴真正读一遍，比表格诚实。

## 5. 建立资产圣经

资产圣经定义整部片中什么不能随镜头漂移。每项资产分配项目级 ID，例如 `角色01`、`场景02`、`道具03`。项目级 ID 用于管理文件，不等同于 Prompt 内的 `<Subject N>`。

### 5.1 角色圣经

每个主要角色记录：

```text
角色ID：角色01
姓名：
年龄段与体型：
面部识别特征：
发型与发色：
肤色与皮肤质感：
常态表情与身体姿态：
服装版本：服装01A / 服装01B
配饰：
声音：音色、音高、语速、口音、呼吸特征
禁止变化：
参考素材文件：
```

人物参考建议至少准备：

- 清晰正面或轻微三分之四侧脸近照。
- 半身或全身比例参考。
- 当前场景服装参考。
- 特殊妆容、伤痕或湿发状态参考。

每条生成不必上传所有人物图。通常选择 1–3 张与当前景别和状态最匹配的参考即可。互相冲突的发型、光线、妆容和年龄状态不要同时上传。

### 5.2 场景圣经

记录空间中稳定不变的内容：

- 空间布局、入口、窗户、桌椅和关键道具位置。
- 主光方向、色温、明暗关系和时间段。
- 墙面、地面、材质、天气和环境状态。
- 适用景别和禁止出现的现代/历史元素。
- 角色在空间中的常用运动方向。

同一场景建议准备一个建立镜头参考、两个常用机位参考和必要的局部道具参考。场景图片如果只定义环境，应作为 `<Subject N>` 的来源；只有它本身承担具体首帧、关键帧、尾帧或构图锚点时，才单独定义 `<Picture N>`。

### 5.3 服装与道具圣经

记录：

- 服装版本及其适用场次。
- 外套是否穿着、敞开、淋湿或受损。
- 鞋、首饰、眼镜、包、武器等状态。
- 道具由哪只手拿、朝向、开合和损坏状态。
- 剧情状态发生变化的准确镜头。

AI 生成最爱在没人注意时给角色换戒指、换手拿杯子、把湿外套烘干。连续性总表就是专门逮这些小动作的。

### 5.4 动作与运镜参考

参考视频必须为 2–15 秒。准备时：

- 一个视频只承担一个清晰动作或运镜职责。
- 保留动作起点、中间变化和结束状态。
- 避免人物被遮挡、镜头乱晃或动作主体过小。
- 只参考动作时，将动作定义为 `<Subject N>`；整段视频只在提供剪辑、运镜、节奏或源视频关系时定义为 `<Video N>`。

### 5.5 声音圣经

每个主要角色建立干净音色样本：

- 时长 2–15 秒，建议包含自然停顿和完整句子。
- 无背景音乐、无混响、无明显环境噪声。
- 音量稳定，不要多人重叠。
- 记录语言、音高、音色、语速、口音和情绪范围。

区分三种用途：

| 用途 | Ref2VA 关系 | 含义 |
| --- | --- | --- |
| 完整音轨直接使用 | `fully_copy` | 源音频成为完整最终音轨 |
| 使用部分信号或声部 | `partially_copy` | 只复制选定时间、对白或声音层 |
| 只模仿音色/语速/节奏 | `reference` | 不复制源信号，只作为生成指导 |

只参考音色时，不得把音色样本里的原对白带入新镜头。

### 5.6 权利与真人安全

- 使用真人脸部、声音和表演参考前取得明确授权。
- 不使用未经同意的公众人物或普通人素材进行冒充、误导或诽谤。
- 保留素材来源、授权范围和使用期限记录。
- 涉及品牌、音乐、字体、服装图案和场地时检查使用权。
- 成片需要披露 AI 生成时，按发布平台规则标注。
- 未成年人、敏感身份和私密场景使用更严格的授权与审查。

技术上能做不等于就该做。真人生成最容易踩的坑不是 Prompt，而是拿别人的脸和声线当免费插件。

## 6. 从剧本拆成镜头表

### 6.1 区分场景、剪辑镜头和生成单元

- **场景**：同一时间地点内的一段剧情。
- **剪辑镜头**：最终时间线中一次连续画面。
- **生成单元**：一次 H3 任务输出的 4–15 秒素材。

一个生成单元可以包含少量切镜，但真人剧情为了人物稳定和后期可控，优先让一个生成单元承担一个主要镜头。正反打最好分别生成，别指望模型在同一条素材里切来切去还帮你守住两张脸。

### 6.2 单个生成单元的任务上限

建议每条只包含：

- 一个主要叙事目的。
- 一个主要动作或状态变化。
- 一种主要情绪变化。
- 一个主要运镜。
- 一段能够自然说完的对白。

推荐时长：

| 内容 | 常用生成时长 |
| --- | --- |
| 反应、插入、物品特写 | 4–6 秒 |
| 单句对白、简单动作 | 6–9 秒 |
| 完整表演、连续动作 | 9–12 秒 |
| 单一长动作或特殊一镜到底 | 12–15 秒 |

这不是硬规则。判断标准是动作和对白能否自然完成，而不是把每格都塞满。

### 6.3 镜头表字段

```text
镜头ID：场01_镜003
预计成片时长：7 秒
生成时长：9 秒
叙事目的：林夏发现车票但假装没有看见
开场状态：车票露出桌角，林夏刚放下湿外套
结束状态：林夏的手停在车票上方，视线转向厨房
景别与构图：中近景，林夏位于左侧，桌面在前景
人物与状态：角色01，服装01A，湿发，右手持伞
场景：场景01，深夜客厅
主要动作：放下外套 → 看到车票 → 手伸向车票 → 停住 → 看向厨房
运镜：缓慢小幅 push in
对白：无
同步声音：湿外套摩擦、手机振动、冰箱低鸣
参考素材：角色01正面、服装01A、场景01机位B、车票道具
连续性要求：车票在桌面右侧；伞始终在右手；厨房位于画面右侧
剪辑入口：开头稳定约 0.5 秒
剪辑出口：结束姿态保持约 0.5 秒
状态：待写提示词 / 待生成 / 待审 / 批准 / 返修
```

### 6.4 给剪辑预留把手

生成素材不要一开场就完成动作，也不要最后一帧还在剧烈运动。条件允许时：

- 开头保留约 0.5–1 秒稳定状态。
- 结束保留约 0.5–1 秒稳定姿态或自然延续动作。
- 明确动作从哪里开始、在哪里落下。
- 需要对切时保留视线和呼吸反应。

这些“把手”给后期留出切点、叠音和节奏调整空间。没有把手的素材就像门上没装把手，理论上也能开，实际全靠抠。

### 6.5 连续性规则

逐镜检查：

- 视线方向是否匹配。
- 人物运动是否保持屏幕方向。
- 道具是否换手、消失或变形。
- 服装、袖口、纽扣、湿度、污渍和伤痕是否一致。
- 场景布局、主光方向和时间是否一致。
- 前一镜结束动作是否能接后一镜开始动作。
- 人物情绪是否有合理过渡。

难以连续生成的动作可以拆成：动作前反应 → 道具特写 → 动作结果。剪辑是解决 AI 物理问题的正当工具，不是作弊。

## 7. 为每个镜头建立 Ref2VA 提示词包

### 7.1 提示词文件结构

每个镜头独立一个 Markdown 文件：

```text
# 场01_镜003

## 生成配置（不属于 Prompt）

- 模式：Ref2VA
- 时长：9 秒
- 画幅：9:16
- 分辨率：768p
- 目标成片时长：7 秒

## 素材映射（上传顺序）

| 上传素材 | 项目资产 | 本镜头职责 |
| --- | --- | --- |
| 图片1 | 角色01正面 | 人物身份、脸、发型 |
| 图片2 | 服装01A | 红色羊毛外套 |
| 图片3 | 场景01机位B | 客厅布局、光线、构图 |
| 图片4 | 前镜批准末帧 | 本镜头具体首帧锚点 |
| 音频1 | 角色01音色 | S1 音色参考，不复制原句 |

## Prompt

[在此放置六字段英文/中文 Prompt]

## 生成记录

| 版本 | 日期 | 结果 | 问题 | 下一版只修改什么 |
| --- | --- | --- | --- | --- |
```

项目资产 ID 在整部片中固定；`<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 是当前 Prompt 内部标签。为了减少出错，可在同一场景的一组 Prompt 中尽量维持相同映射，但模型只要求标签在当前六字段内含义一致。

### 7.2 六字段顺序

正式 Prompt 必须全部使用英文/中文结构正文，并严格按以下顺序：

```text
subject_definitions:
...

summary:
...

retention_analysis:
...

detailed_description:
...

overall_soundscape:
...

non_diegetic_music:
...
```

对白、歌词和画面可见文字保留原文语言。对白写入 `<d>[Language] ...</d>`，可见文字放入英文双引号。

### 7.3 标签职责

| 标签 | 真人剧情常见用途 |
| --- | --- |
| `<Subject N>` | 人物、服装、场景、道具、动作、姿势、表情或视觉效果 |
| `<Picture N>` | 具体首帧、关键帧、尾帧、构图或故事板锚点 |
| `<Video N>` | 源视频编辑、视频续接、整段运镜、剪辑节奏或时序结构 |
| `<Audio N>` | 完整/部分音轨复制，或音色、对白、节拍、音乐风格、音效纹理参考 |

图片只提供人物身份时，在人物 `<Subject N>` 定义中注明图片来源，不必额外创建独立 `<Picture N>`。参考视频中的动作可以定义为 `<Subject N>`；只有整段视频关系才定义 `<Video N>`。

标签一旦分配，在当前 Prompt 的定义、摘要、保留分析、逐镜描述和声音字段中必须保持同一含义。`<Video N>` 与 `<Audio N>` 分别独立编号，序号相同不代表来自同一个文件。普通参考视频即使包含声音，也不会自动产生 `<Audio N>`；只有当该音轨被复制或参考时才定义 Audio 标签。

### 7.4 `summary` 任务类型

从以下固定值中选择，可用 ` + ` 组合：

- `keyframe completion`
- `reference generation`
- `video editing`
- `video continuation`
- `audio reuse`
- `audio reference`

角色图、场景图、动作视频和音色共同指导新镜头，常见写法：

```text
[reference generation + audio reference] ...
```

上一镜末帧作为本镜具体开场锚点时加入：

```text
[keyframe completion + reference generation + audio reference] ...
```

### 7.5 `retention_analysis` 固定关系

可见内容只使用：

- `fully_preserved`
- `partially_preserved`
- `attribute_transfer`
- `weak_reference`

音频只使用：

- `fully_copy`
- `partially_copy`
- `reference`
- `weak_reference`

不要把“新增一个动作”误判为人物未完全保留。关系标记评估的是该标签定义的职责，而不是目标视频有没有新剧情。

### 7.6 `detailed_description` 写法

生成类任务通常写 350–500 个英文/中文单词。先在 `[Shot 1]` 前用一两句确定媒介、风格、光线和色彩，再按播放顺序描述：

```text
composition
→ subject identity and position
→ environment and lighting
→ action and state change
→ camera movement
→ synchronized sound/dialogue
→ stable end state
```

Ref2VA 镜头文件通常只生成一个主要镜头，因此 `[Shot 1]` 不需要时间戳。确实需要同一生成单元内切镜时，后续镜头使用严格递增的切点：

```text
[Shot 2] At 00:05.000, the camera cuts to...
```

不要写 `0–5s`、`5–9s` 代替正式 Shot 格式。

### 7.7 说话者和对白

- 当前生成单元按实际首次发声顺序分配 `(S1)`、`(S2)`。
- 项目级角色 ID 与 `(Sx)` 分开管理；不要假设角色01在所有镜头中必然都是 `(S1)`。
- 参考角色发声时写 `<Subject N> (Sx)`。
- `<d>` 内只放语言标签和原始对白，不翻译、不润色。
- 画外音使用 `says in an off-screen voiceover`，并声明对应画面人物嘴唇闭合。
- 对白跨切镜使用 `<scenetrans>`；结尾截断使用 `<cutoff>`。

```text
<Subject 1> (S1) looks toward the kitchen and says in a restrained, breathy voice: <d>[Chinese] 你什么时候买的票？</d>
```

### 7.8 Ref2VA 单镜头模板

```text
subject_definitions:
<Subject 1> is [character identity] from <Picture 1>, preserving [face, hair, body proportions, and current costume].
<Subject 2> is [environment] from <Picture 2>, preserving [layout, materials, lighting, and key props].
<Subject 3> is [action, pose, expression, or object] from <Picture/Video N>.
<Picture 3> is the exact first frame or last frame of [Shot 1], defining [composition and state].
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).

summary:
[keyframe completion + reference generation + audio reference] The target video shows <Subject 1> [main narrative action] in <Subject 2>, follows <Subject 3> for [specific role], uses <Picture 3> as [frame role], and follows <Audio 1> for voice timbre.

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - [specific identity, costume, and body features].
<Subject 2> (appears in [Shot 1]): fully_preserved - [specific environment and lighting features].
<Subject 3> (appears in [Shot 1]): fully_preserved - [specific action or pose path].
<Picture 3> ([Shot 1] first/last frame): fully_preserved - [specific composition and state].
<Audio 1>: reference - its [timbre and delivery] guide (S1) without copying the source signal.

detailed_description:
The target video uses a live-action cinematic style with [lighting, contrast, color, and texture].
[Shot 1] [Initial composition and frame anchor]. [Describe referenced subjects, positions, and environment]. [Describe the complete observable action path]. [Describe one primary camera movement]. [Insert exact dialogue and synchronized sound when present]. [End on a stable, editable state or required frame anchor].

overall_soundscape:
[Ambient bed, physical action sounds, and non-verbal human sounds].

non_diegetic_music:
N/A
```

方括号内容是占位符，提交前全部替换。模板里写 `N/A` 是因为长片对白镜头通常建议后期统一配乐；若当前镜头确实需要独立观众侧音乐，再用英文/中文描述乐器、节奏和动态变化。

## 8. 长片声音策略

### 8.1 三种对白方案

| 方案 | 优点 | 风险 | 适用场景 |
| --- | --- | --- | --- |
| H3 每镜头直接生成对白 | 画面、口型和声音一起生成 | 跨镜音色、语气和录音质感可能波动 | 少量对白、风格化短剧 |
| 预先录制对白并作为音频复用/参考 | 节奏、台词和音色更可控 | 需要按 2–15 秒切片并处理口型 | 对白驱动剧情 |
| 生成画面后统一后期配音 | 声音一致性和剪辑自由度最高 | 口型匹配难，需要避免长时间正面说话 | 画外音、旁白、侧脸或非同步对白 |

3–5 分钟真人剧情优先先锁定对白节奏。可以使用真人录音、合法授权的音色或临时配音进行剪辑预演，再决定哪些镜头必须由 H3 原生生成口型。

### 8.2 不要让每条素材各自配一段 BGM

如果每个镜头独立生成配乐，拼接后通常会出现调性、节拍、音色和混响不断重启的问题。推荐：

- 大部分对白和动作镜头使用 `non_diegetic_music: N/A`。
- 保留 H3 生成的对白、动作音效和环境基础。
- 在后期按整场或整片统一铺设配乐。
- 需要音乐卡点的镜头，先确定最终音乐，再准备对应节拍参考。
- 场景内角色能听见的收音机、手机、现场演奏属于画内音乐，写入 `detailed_description`，不是 `non_diegetic_music`。

### 8.3 建立环境声连续性

同一场景使用统一的环境底：雨声、空调、街道、虫鸣、房间混响等。剪辑时用连续环境声覆盖镜头切点，可以显著减少不同生成素材之间的听觉断裂。

字幕、片头文字和对白字幕尽量在后期制作，不要让生成模型在每个镜头中反复生成相同文字。

## 9. 生成生产流程

### 9.1 先测试最难的三类镜头

不要从场01镜001一路顺序生成。先测试：

1. 主角最重要的正面对白近景。
2. 两个角色同框或强互动镜头。
3. 最复杂的动作、道具或连续性镜头。

这三类通过后才能证明角色参考、音色和动作方案可用。开场空镜生成得再漂亮，也证明不了主角能不能把话说利索。

### 9.2 锁定资产后分批生成

可以按以下方式分批：

- 同一场景与光线。
- 同一服装状态。
- 同一角色组合。
- 同类景别或镜头语言。
- 同一音频方案。

批量生成前，先批准该批次的一个标准镜头。其余 Prompt 复用同一资产定义和连续性约束，但每条仍只写当前镜头动作。

### 9.3 每个版本只改一个主要变量

生成失败后记录：

- 身份是否稳定。
- 动作在哪个节点失败。
- 构图、运镜或表情是否错误。
- 对白、口型、音色或环境声是否错误。
- 参考标签是否定义过多或职责冲突。

下一版优先只修改一个主要失败点。一次同时改人物图、场景图、动作、机位、时长和台词，成功了也不知道为什么，失败了更不知道该骂谁。

### 9.4 生成记录

`生成记录.csv` 至少包含：

```text
镜头ID,版本,生成日期,时长,提示词文件,参考素材,身份,动作,构图,口型,音色,声音,连续性,结论,问题,下一步
```

结论统一使用：

- `批准`
- `可剪辑修复`
- `需重生成`
- `废弃`

禁止靠记忆判断哪个版本最好。生成到第二十条以后，人脑对 `版本03` 和 `版本05` 的差异基本只剩玄学。

### 9.5 每条素材验收

批准前逐帧或低速检查：

- 脸、发型、体型和年龄是否漂移。
- 手、牙齿、眼睛和道具是否异常。
- 服装、首饰和伤痕是否与连续性表一致。
- 动作有没有瞬移、穿插、倒放或物体变形。
- 运镜是否符合方向和速度。
- 台词是否完整、原文正确、口型可接受。
- 画外音时画面角色是否保持闭口。
- 环境声、动作声和人声是否冲突。
- 开头和结尾是否有可用剪辑点。
- 可见文字是否准确；错误文字能否后期替换。

批准后导出末帧、关键帧和必要的角色状态图，供后续镜头连续性参考。

## 10. 常见失败与修复

| 问题 | 原因 | 优先修复 |
| --- | --- | --- |
| 人脸跨镜漂移 | 参考图冲突、景别差异过大、递归生成累积 | 回到原始主角色图；减少参考数量；明确身份特征；使用批准关键帧 |
| 服装和发型改变 | 状态定义不明确 | 建立服装版本；每镜头注明版本和禁止变化特征 |
| 两个人融合或互换 | 同框关系复杂、Subject 定义不清 | 分别定义人物与位置；减少交叉动作；改用正反打 |
| 手和道具异常 | 复杂抓取或遮挡 | 拆分动作；用插入镜头；让动作在清晰平面内完成 |
| 动作突然跳到结果 | 缺少中间状态 | 写出接触、施力、移动、结果和稳定状态的因果链 |
| 镜头接不上 | 开始/结束状态未定义 | 使用前镜末帧；预留把手；记录视线、屏幕方向和道具状态 |
| 对白说不完 | 台词过长或镜头过短 | 朗读计时；删词；拆镜；用反应镜头或画外音承载 |
| 口型不稳定 | 多人同时讲话、遮挡、语速过快 | 单人近景；缩短对白；固定说话者 ID；调整音频方案 |
| 音色跨镜变化 | 每镜独立生成、参考样本不干净 | 统一音色样本；后期配音；对所有镜头使用一致声音圣经 |
| BGM 每镜重启 | 各条独立生成音乐 | 生成时设 `N/A`，在后期统一配乐 |
| 场景布局变化 | 场景参考角度单一或职责含糊 | 增加同场景机位参考；明确固定空间关系 |
| 生成内容太“AI” | 皮肤、光线、动作和镜头都过度完美或风格词堆砌 | 增加真实材质、呼吸、微动作和物理声；减少抽象形容词 |
| 字幕或标牌乱码 | 生成模型承担大量文字 | 后期制作文字；生成画面只保留干净区域和必要遮挡关系 |

不能修复的镜头不一定必须重生成，可以使用：

- 提前切出。
- 插入手部、道具、环境或反应镜头。
- 用 J-cut/L-cut 让声音跨镜延续。
- 裁切重构图。
- 速度微调，但不要破坏对白和自然动作。
- 用环境声和配乐掩盖音频接缝。

## 11. 后期制作流程

### 11.1 粗剪

1. 只使用批准或可修复素材建立故事顺序。
2. 先看叙事是否成立，不急着加转场和特效。
3. 删除重复信息、无效停顿和漂亮但没用的镜头。
4. 使用临时对白和音乐确认节奏。
5. 形成粗剪后重新检查缺镜，而不是凭剧本猜缺镜。

### 11.2 补镜

粗剪会暴露真正需要的素材，常见补镜：

- 建立空间的空镜。
- 人物反应镜头。
- 手、手机、信件、钥匙等道具插入镜头。
- 从一个场景过渡到另一个场景的视觉桥梁。
- 用来遮挡对白剪辑的侧脸、背影和环境镜头。

这些低风险镜头往往比继续死磕一个失败的复杂镜头更值钱。

### 11.3 画面锁定

故事节奏和镜头长度确定后锁定画面，再进行：

- 最终高分辨率再生成或放大。
- 统一裁切和稳定。
- 镜头间曝光、白平衡、对比度和肤色匹配。
- 必要的修补、遮罩、清理和合成。
- 最终文字、Logo、片头和字幕。

不要在粗剪阶段给所有候选镜头做高成本精修。给废片上妆，还是废片，只是妆挺贵。

### 11.4 声音后期

按以下层级组织：

1. 对白与旁白。
2. 必要的动作音效。
3. 连续环境声与空间混响。
4. 音乐。
5. 最终整体响度与峰值控制。

处理跨镜音色、噪声和房间质感差异。对白必须始终可懂，音乐不能在关键台词上硬压。对白修改完成后再锁字幕。

### 11.5 最终交付检查

- 片头是否迅速进入事件。
- 3–5 分钟内是否存在明显拖沓段落。
- 所有角色身份、服装和道具状态是否连贯。
- 是否有手、脸、牙齿、眼睛和物理异常漏检。
- 台词是否完整、准确、清楚。
- 声音是否存在突然断裂、音色跳变或左右声道异常。
- 字幕与对白是否同步，错别字是否清零。
- 可见品牌、肖像、音乐和素材是否有授权。
- 输出画幅、分辨率、帧率、编码和音频规格是否符合平台要求。
- 是否保留无字幕母版、字幕版和项目归档。

## 12. 阶段门禁

每个阶段有明确交付物，未通过就不进入下一阶段：

| 阶段 | 必须交付 | 通过条件 |
| --- | --- | --- |
| 创意 | 创作简报、一句话梗概 | 目标观众、冲突、结局明确 |
| 剧本 | 锁定剧本、朗读时长 | 3–5 分钟内成立，角色和场景受控 |
| 预生产 | 五类资产圣经、参考素材 | 人物、声音、场景和服装可稳定复用 |
| 样片 | 30–60 秒完整片段 | 身份、口型、声音、剪辑和风格可接受 |
| 分镜 | 场景表、镜头表 | 每条 4–15 秒，可执行且能衔接 |
| 生成 | 提示词包、版本记录、批准素材 | 每条通过镜头验收，连续性记录更新 |
| 粗剪 | 完整故事粗剪 | 叙事成立，明确补镜清单 |
| 精修 | 画面锁定、调色、声音和字幕 | 技术与内容 QA 通过 |
| 交付 | 母版、发布版、归档 | 平台规格与授权记录完整 |

## 13. 最小可执行清单

第一次做项目时，按这个顺序就够了：

- [ ] 填写创作简报。
- [ ] 从想法生成 3 个故事方向并选定一个。
- [ ] 完成节拍表、场景表和锁定剧本。
- [ ] 朗读并计时全部对白。
- [ ] 建立角色、场景、服装道具、视觉和声音圣经。
- [ ] 制作 30–60 秒高难度样片。
- [ ] 根据样片修改并锁定参考素材。
- [ ] 将全片拆成 4–15 秒生成单元。
- [ ] 为每个镜头建立配置、素材映射和六字段 Prompt。
- [ ] 先生成最难镜头，再按批次生产。
- [ ] 每个版本写入生成记录，每次只改主要失败点。
- [ ] 批准镜头后导出连续性关键帧。
- [ ] 完成粗剪，再按真实缺口补镜。
- [ ] 画面锁定后统一高分辨率、调色、配音、混音和字幕。
- [ ] 完成内容、技术和权利检查后交付。

1. `references/真人短视频创作指南.md`：本指南的完整制作流程、模板、连续性、后期和 QA。
